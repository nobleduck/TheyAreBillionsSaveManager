# They Are Billions 存档回退工具

## 目标与授权

用户要求直接制作下次可用的程序，放在 E:\code\gitproject，建立本地 Git 仓库，为以后发布源码做准备。本次交付中文 Windows GUI、可执行文件、源码和测试；开发过程中不回退用户正在进行的游戏。

## 选择

采用 .NET Framework 4.x / WinForms / C# 5，使用 Windows 自带 csc 构建，零第三方运行依赖。相对 Python 打包和本地网页服务，这种方式产物小、启动直接。以 Windows 10/11 为运行目标。

## 已验证的问题

游戏存档包含同名 .zxsav / .zxcheck 配对文件。自动备份名称带 _Backup，恢复时保留原文件名。Steam 启动前会重新下载缺失的当前存档，因此在游戏退出时移除当前文件不足以完成回退。

实际成功流程是：通过 Steam 启动游戏，等待当前启动会话进入主菜单，移开这一局的较新存档，保留目标备份，再让用户点击继续。日志必须出现目标文件的 Loading game，随后出现 Gamestate Loaded，才能确认读入。

## 用户界面

- 原生中文窗口，显示存档位置、快照位置、游戏状态与操作进度。
- 当前存档页列出配对存档的保存时间、类型、大小。选择自动备份时显示相对同局当前存档的时间差。
- 历史快照页列出已保留的配对文件，可按原文件名恢复。
- 手动备份、刷新、打开快照目录、选择存档目录、启动游戏并回退。
- 开启工具时可选择自动保留发生内容变化的存档，默认每 15 秒检查；仅复制已写盘的完整且稳定的配对，不伪造新的游戏保存点，不自动删除历史。
- 回退按钮只在游戏未运行时可用。流程中明确提示不要提前点继续，主菜单处理完后显示可以继续。只在读档日志确认后显示已加载；云端上传完成是单独的事实，不能由本地加载推断。

## 数据与边界

- 数据默认保存到 LocalApplicationData/TheyAreBillionsSaveManager，绝不写入 Git 仓库。
- 快照不可变，记录文件长度、SHA-256、原始修改时间、原因。读取允许游戏继续写入，要求文件至少稳定一秒，并在复制后复查长度、时间和哈希；修改时间差超过五秒时拒绝该配对，等待下次检查，避免工具阻塞游戏自动保存。
- 快照目录和存档目录不能互相包含。拒绝文件名穿越和操作路径中的重解析点。
- 执行回退前再保存一份当前状态。四个相关文件的移除与目标配对放置有持久事务记录；原件移动到 Saves 同级恢复目录，保留可人工恢复的副本。
- 在每次文件修改前重新检查同一进程仍停在主菜单。提前进入存档选择、加载、退出、日志错误或超时都停止。发生部分错误时仅填回缺失的原件，绝不覆盖外部新写入。
- 启动等待最多三分钟；文件准备后等待读档最多十分钟。日志必须有新会话起点，且只接受文件准备之后的目标加载事件。文件操作结束还要检查较新文件没有重新出现。
- 恢复目标只接受经过清单验证的本工具快照；保留目标原始文件名，包括 _Backup。不得修改 Steam 设置、云端内容、账户或其他游戏存档。
- 程序不强制关闭游戏，不操纵游戏进程或自动点击游戏界面。

## 实现边界

Models 定义数据；SaveStore 负责配对和快照/事务；GameLog 解析会话；RollbackCoordinator 管理状态转换；WindowsGameHost 只负责启动与观察进程/日志；MainForm 负责呈现。进程与时间作为测试边界，文件操作使用临时目录中的真实文件。

## 验证

测试配对完整性、变化去重、损坏清单、路径穿越、文件占用、错误时间、事务部分失败、其他存档隔离、启动时云端补回文件、提前点击继续、过期日志、错误存档路径和正确加载事件。GUI 在测试进程中渲染预览并检查布局。实际游戏只读扫描，不执行真实回退。
